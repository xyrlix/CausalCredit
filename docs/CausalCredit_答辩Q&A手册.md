> **目的**: 6.15 提案 / 6.16+ 答辩 高频质疑 + 标准回应 + 翻车兜底

## Q1 「AUC 只有 0.78, 业界都 0.81+ 了?」

**标准回应 (李定泉)**:
> "AUC 0.7803 是 Home Credit 公开数据的真实测试结果, 接近 Kaggle leaderboard 0.81 水平, 这部分在 pipeline 报告里有打印。但 CausalCredit 的定位不是'刷榜', 是**'预测 → 因果 → 决策 → 反欺诈'**的闭环, 我们的价值在 AUC 之外: 同一个申请人能拿到 4 件事 (分数 / 归因 / 反事实 / 决策报告), 这是传统评分模型做不到的。"

**翻车兜底**:
- "如果评委问 '那你们为什么不去刷到 0.81', 我们承认: 已经做过 5-fold CV + LightGBM + GPU 调优 (M6 完工), 在当前特征工程下基本到天花板; 再投入产出比低, 我们选择把精力放在因果层。这是工程取舍。"
- "对照表: 5.4 节差异化, 我们在 可解释性 / 因果推理 / 决策建议 3 个维度都是 ★★★★★, 远超传统方案。"

---

## Q2 「反欺诈用伪标签, 学术上站不住脚啊?」

**标准回应 (李定泉)**:
> "M7 反欺诈三件套的伪标签是我们**主动声明**的概念验证, 不是要替代真实标注。伪标签的 4 条业务规则 (DPD > 30 天 / 高收入 + 低在职 / 外部分低 + 高收入 / 行业风险) 来自零售信贷常见模式, 是**业务可解释规则**而非统计拟合。"

**翻车兜底**:
- "M7 文档里我们写明: `fraudulent` 和 `systemic` 两类是按业务规则触发, 这在 Phase 2 必须用银行真实标注替换, 已经在落地路线图里。"
- "但要注意: 反欺诈三件套的**架构** (4 维评分 + 5 级路由) 是有学术依据的, 包装资质和养流水去噪的因果路径是我们原创。"
- "评委若追问, 关键话术: '我们没有用伪标签做最终决策, 我们用伪标签**证明方法论能跑通**, Phase 2 校准不需要重写代码'。"

---

## Q3 「Home Credit 不是 BOCHK 数据, 凭什么说能落地?」

**标准回应 (陈天元)**:
> "Home Credit 是**方法论验证平台**, 因果图是变量级而非样本级, 18 个节点的领域 DAG 拿到 BOCHK 脱敏数据后, 节点 (比如 '收入/教育/在职天数') 是同质的, 边 (因果关系) 不需要重画。我们要换的是**先验概率** (大湾区 vs 东欧的薄信用人群分布不同), 不是**因果机制**。"

**翻车兜底**:
- "M8.1 公平性审计对位 HKMA & EU AI Act 的 3 项指标 (DP/EO/DI), 我们主动披露了 WARNING 状态, 这证明我们对监管要求是认真对位的。"
- "三阶段路线图 (5.1 节) 写明: Phase 2 银行试点需要 3-6 个月 + 信贷/风控/合规三方协调, 不是 1 周能交付的, 这就是诚实边界。"

---

## Q4 「因果发现真的可信吗? 不是数据巧合?」

**标准回应 (李定泉)**:
> "我们的因果发现是**三路融合**: PC 算法 (约束型) + NOTEARS (评分型) + 领域 DAG 注入 (18 节点 / 36 边), 然后用 DoWhy 的 4 类 refuter + E-value 主动攻击:
> 1. Placebo treatment: 把处理变量换成噪声, 看 ATE 是否消失 → PASS
> 2. Random common cause: 加一个随机混杂, 看 ATE 是否稳定 → PASS
> 3. Data subset: 切 5 个子集, 看 ATE 符号是否一致 → PASS
> 4. E-value: 未观测混杂要多强才能推翻结论 → 给出数值
>
> 合成数据上边召回率 100%, 真实数据与领域 DAG 重叠率 100% (5/5 关键边), 测试在 `tests/test_causal_discovery.py` 5 个 case 全过。"

**翻车兜底**:
- "我们也承认: 真实数据 5/5 重叠**不是 100% 因果正确**, 是**与领域知识完全一致**; 评分要诚实地说是'领域一致性指标', 不是'真值召回'。"
- "评委若要求'证明因果正确', 唯一办法是做 RCT (随机实验), 但 BOCHK 上线 RCT 不现实。我们用 refuter + E-value 是**当前最佳实践**。"

**标准回应 (李定泉)**:

## Q6 「凭什么说能迁移到 BOCHK 生产?」

**标准回应 (陈天元)**:
> "三阶段路线, 写在 5.1 节: **Phase 1 (现在) Home Credit 验证方法论** → **Phase 2 (3-6 月) 银行脱敏数据试点** → **Phase 3 (6-12 月) 生产嵌入**。我们**不承诺** Phase 3 时间表, 因为这取决于 BOCHK 的合规审批节奏, 不取决于我们。但 Phase 1 + Phase 2 是我们能交付的, 也都列了资源需求。"

**翻车兜底**:
- "若评委问'那你们现在能直接给 BOCHK 用吗', 老实答: '不能, M8.1 公平性有 WARNING, M7 反欺诈是概念验证, 必须 Phase 2 校准'。"
- "强调: '我们交付的是**方法论 + 验证平台**, 不是产品; 这是诚实的边界'。"

## Q7 「SHAP × 因果四象限有学术先例吗?」

**标准回应 (李定泉)**:
> "SHAP (Lundberg & Lee 2017) 和 DoWhy (Sharma et al. 2019 MIT 2019) 都是成熟工具, 但**两者的组合** + **四象限分类法** (TRUSTED/UNTRUSTED/MASKED/NEGLIGIBLE) 是我们为信贷场景**原创**的组合创新, 有学术发表潜力, 论文草稿在 `docs/CausalCredit_因果推理验证标准体系.md` 已有骨架。"

**翻车兜底**:
- "若评委要论文: '草稿在 docs/, 计划 6.16 后投 KDD 2026 Workshop 或 ICAIF (ACM 金融 AI 会议)'。"
- "若评委要 citation: '我们引用 Lundberg 2017 + Sharma 2019 + 我们的 docs 内部文档', 文档里都有。"

---

## Q8 「DiCE 反事实可执行性? 客户真能改?」

**标准回应 (许海波)**:
> "DiCE 输出包含 3 套候选方案, 每套都带 4 件事:
> 1. **要改的特征 + 改多少** (e.g. AMT_CREDIT -30%)
> 2. **预计风险变化** (e.g. P(default) 0.26% → 0.18%)
> 3. **因果可信度评分** (e.g. 0.85, 0-1)
> 4. **不可变特征锁死** (DAYS_BIRTH/CODE_GENDER/DAYS_ID_PUBLISH/EDUCATION 不能改, 因果约束)
>
> 信贷员拿到的是'按这个调整, 预计违约率降 30%', 不是'模糊建议'。"

**翻车兜底**:
- "若评委问'客户能改的只有 3 个特征吗', 老实答: '生产场景下客户能改的变量是已知的 (额度/收入/在职), 我们的 IMMUTABLE 锁死 + SEMI_MUTABLE 限幅 50% 已经在做这个约束'。"

---

## Q9 「计算成本多大? 需要 GPU 集群吗?」

**标准回应 (许海波)**:
> "**CPU 单机** 即可, 16 步 Pipeline 跑全 ≈ 220 秒 ≈ 4 分钟, 算力成本 **< HK$500** 量级。子步骤成本:
> - LightGBM 训练: < 60 秒
> - PC + NOTEARS 因果发现: < 120 秒
> - DiCE 单样本反事实: < 5 秒
> - 因果叙事 v2 (含 20× 扰动): < 8 秒
>
> **M6 GPU build 已接入但默认关闭**, Optuna 9 维超参搜索也接入但默认关闭。两个可选杠杆, 不开就 CPU 跑, 开了 GPU 提速 2-3x。"

**翻车兜底**:
- "若评委问'生产要多少 QPS', 老实答: 'Phase 1 是离线批量, 不是实时; Phase 3 才有实时需求, 那时要上 K8s (不在我们当前范围)'。"

## Q10 「M8.4 多语言中文金融术语怎么对齐?」

**标准回应 (许海波)**:
> "CausalNarrative.render_markdown 三语 (zh / zh-HK / en), 关键设计:
> 1. **只翻译章节标题 + 表头**, 叙述体保留英文避免歧义 (e.g. 'causal narrative' 这个词)
> 2. **港式措辞** (層面 / 對照 / 穩健性) 参考 HKMA 公开文件的用词习惯
> 3. **多语言是渐进式**, 不是强翻译, 客户可以选英文看技术细节 + 中文看结论
>
> 4 个测试用例 (`test_render_markdown_zh_hk_traditional` 等) 已覆盖 zh / zh-HK / en / 未知语言 fallback。"

**翻车兜底**:
- "若评委问'为什么不翻译叙述体', 老实答: '英文叙述体是 SHAP + DoWhy 论文的标准表达, 强翻译反而损失准确性; 章节标题和表头是评审员会读的部分, 必须本地化'。"

## 冷门追问 (评分较低, 但有可能)

### Q11 「M5 8 表 JOIN 怎么做的? 内存够吗?」

> "**5 张二级表** (bureau / previous_application / POS_CASH / installments / credit_card) 聚合 → 246 特征, 约 1.1GB / 80M 行, pandas 单线程约 27s, 我们做了二级缓存, 第二次跑 < 2s。**只用 5 张表没用 8 张**, 因为 credit_card_balance 在我们初筛中 AUC 增益 < 0.001, 主动裁剪避免过拟合。"

### Q12 「DiCE 跑多久? 能上生产吗?」

> "单样本 < 5 秒, 但**单样本不够**, 生产要批量 (e.g. 100 个申请人并发)。M5 优化的批量 aggregation 思路可借鉴, 但 DiCE NSGA-II 不易并行, Phase 2 会引入近似算法 (e.g. Nearest CF Search) 替代, 速度提升 10x。"

### Q13 「公平性 WARNING 状态不影响评分吗?」

> "**不影响**主评分, 但**影响决策建议**: WARNING 状态下决策建议会附加 'request additional documentation from the applicant'。这是 1.5 节文档里写明的'公平性嵌入决策'设计, 我们没把 WARNING 当装饰。"

### Q14 「PSI 漂移告警阈值怎么定的?」

> "**经验值**: < 0.1 无漂移, 0.1-0.2 中度, ≥ 0.2 告警。这个来自业界的 Evidently / WhyLabs 默认值, 我们在 M4 实现时校验过在 Home Credit 测试集上 PSI 分布稳定 (峰值 0.001), 所以阈值是合理的。Phase 2 上线后会根据真实流量重训阈值。"
