## 二、主题一：GreenLens — ESG漂绿智能检测系统

### 2.1 主题名称与一句话定位

**GreenLens** — 让每一分绿色投资都真实可信：基于NLP+因果推理的ESG漂绿智能检测系统

### 2.2 核心痛点

**痛点来源**：艾伦报告 E2（绿色washing识别，24分，TOP4）× 阿信报告方向#1（9.25分，TOP1）

| 维度 | 痛点分析 |
|------|---------|
| **问题本质** | ESG投资规模爆发式增长（全球超40万亿美元），但漂绿（Greenwashing）现象泛滥。企业ESG报告"自说自话"，声明与实际行为严重不一致，投资者和银行难以辨别真伪 |
| **现有方案不足** | ① 人工审核ESG报告效率极低，无法覆盖海量披露 ② 现有ESG评分机构（MSCI/Sustainalytics/S&P）评分相关系数低至0.5，无法提供一致性判断 ③ 缺乏自动化工具验证"ESG声明→实际行动"的因果链 |
| **真实案例** | 2024年德意志银行旗下DWS因ESG漂绿被SEC罚款1900万美元；香港证监会多次就ESG基金披露不充分发出警示 |
| **痛感强度** | ⭐⭐⭐⭐⭐ — 监管趋严+投资规模爆发，刚需且紧迫 |

### 2.3 数据集选型

| 数据集角色 | 数据集名称 | 规模 | 核心特征 | 为什么选它 |
|-----------|-----------|------|---------|-----------|
| **主数据集** | S&P 500 ESG Risk Ratings | ~500家公司 | E/S/G分项风险分+总分+行业+行业排名 | 真实S&P数据，ESG风险量化标签直接可建模，特征清晰 |
| **主数据集** | S&P 500 ESG Sustainability Reports | S&P 500公司文本 | 预处理文本+命名实体+年份 | NLP友好，ESG报告原文可直接做文本-行为一致性检测 |
| **辅助数据集** | ESG Greenwashing: Energy & Industrials | 能源/工业公司 | 漂绿标签+ESG声明文本 | 唯一面向漂绿检测的开源数据集，直接提供正负样本 |
| **辅助数据集** | ESG & Financial Performance Dataset | 1,000家公司×9行业×7地区 | Revenue/Profit/ESG Score/Carbon Emissions | 财务-ESG交叉验证，支撑因果链分析 |

**数据集如何决定模型选型**：

```
数据集特性分析：
├── S&P 500 ESG Reports（文本数据）→ 决定使用NLP模型（FinBERT/FinGPT微调）
├── ESG Greenwashing（标签数据）→ 决定可做有监督分类（漂绿/非漂绿二分类）
├── S&P 500 ESG Risk Ratings（结构化评分）→ 决定可做评分-声明一致性建模
└── 多源数据融合特性 → 决定需要跨模态对齐（文本特征↔数值特征）

模型选型结论：
FinBERT（文本编码）+ 结构化特征融合 + 因果推理验证层
而非强行用GNN或大模型——数据集无图结构，无需GNN；数据量适中，无需大模型
```

### 2.4 技术方案

#### 核心技术栈

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| 文本编码层 | FinBERT（ProsusAI） | 金融领域预训练，110M参数，单卡可训，PhraseBank上F1=0.87+ |
| 特征融合层 | Attention-based Multi-Source Fusion | 文本特征（768维）+ 结构化ESG评分（~20维）→ 注意力加权融合 |
| 因果验证层 | DoWhy因果图 + 反事实推理 | 验证"ESG声明→实际行动"的因果链，而非仅相关性 |
| 可解释层 | SHAP + 证据链生成 | 输出漂绿评分+具体不一致证据（哪项声明与哪项行为矛盾） |
| 部署层 | FastAPI + Streamlit Demo | 轻量级API+可视化Demo，评委可直接体验 |

#### 模型架构

```
输入：ESG报告文本 + ESG评分数据 + 财务数据
  │
  ├─[文本路径] FinBERT编码 → 768维文本嵌入 → ESG声明语义向量
  │
  ├─[数值路径] 结构化特征工程 → 标准化 → ESG行为指标向量
  │
  ├─[融合层] Cross-Attention Fusion → 声明-行为一致性向量
  │
  ├─[因果验证] DoWhy因果图 → 声明→行为因果效应估计 → 反事实对比
  │
  ├─[分类头] 漂绿评分（0-100）+ 不一致证据链
  │
  └─[输出] 漂绿概率 + 证据摘要 + 建议行动
```

#### 创新点

1. **声明-行为因果链验证**：不只做文本分类，而是用因果推理验证"声称做了什么"和"实际做了什么"之间的因果一致性——这是现有ESG评分机构都不具备的能力
2. **多粒度漂绿评分**：公司级→项目级→声明级三层评分，而非简单的"漂绿/非漂绿"二分类
3. **可解释漂绿证据链**：输出具体的不一致证据（如"声称2025年碳减排30%，但碳排放数据实际上升12%"），满足HKMA可解释性要求

### 2.5 价值亮点

## 三、主题二：RiskSense — 风险偏好动态评估引擎

### 3.1 主题名称与一句话定位

**RiskSense** — 从"你说了什么"到"你做了什么"：基于交易行为的风险偏好动态评估引擎

### 3.2 核心痛点

**痛点来源**：艾伦报告 W2（风险偏好评估失真，26分，TOP1）× 阿信报告方向#3（LLM智能投顾，8.75分，部分重叠）

| 维度 | 痛点分析 |
|------|---------|
| **问题本质** | 传统KYC2问卷是"声明式"评估——客户说自己能承受30%回撤，但实际跌5%就投诉。这种"自述-行为"偏差是理财投诉的第一大根源。60%+客户自评为"平衡型"，但实际持仓波动容忍度远低于自评 |
| **现有方案不足** | ① 问卷式评估仅捕捉时点偏好，无法动态追踪 ② 现有智能投顾（如WeLab、8 Securities）仍依赖问卷+简单规则 ③ 缺乏"声明偏好 vs 行为偏好"的偏差量化工具 |
| **真实案例** | 2024年港股波动期，大量客户因无预警导致浮亏超20%才被动关注；银行因"适当性管理"不力被监管处罚的案例逐年增加 |
| **痛感强度** | ⭐⭐⭐⭐⭐ — 艾伦评分最高痛点之一（26分），BOCHK理财核心业务 |

### 3.3 数据集选型

| 数据集角色 | 数据集名称 | 规模 | 核心特征 | 为什么选它 |
|-----------|-----------|------|---------|-----------|
| **主数据集** | Recommended Portfolio for Clients | 客户-资产组合 | 风险偏好+资产配置比例+客户属性 | 直接面向风险偏好-资产配置场景，有风险偏好标签 |
| **主数据集** | Bank Customer Segmentation (1M+) | 100万+交易 | 客户ID/交易金额/类别 | 真实交易行为数据，可构建行为风险画像 |
| **辅助数据集** | Yahoo Finance Dataset (2018-2023) | 多资产5年日线 | OHLCV+Volume | 市场行情数据，构建市场波动事件与客户行为的关联 |
| **辅助数据集** | Banking Dataset - Marketing Targets | 11,162条 | 17属性(年龄/职业/婚姻等) | 客户人口学特征，辅助风险偏好建模 |

**数据集如何决定模型选型**：

```
数据集特性分析：
├── Bank Customer Segmentation（交易序列数据）→ 决定使用序列建模（Transformer/LSTM）
├── Recommended Portfolio（风险偏好标签）→ 决定可做有监督学习（风险偏好分类/回归）
├── Yahoo Finance（市场行情时序）→ 决定需要市场-行为关联建模（多变量时序）
└── 客户属性（结构化特征）→ 决定需要特征融合（序列特征+静态特征）

模型选型结论：
LSTM/Transformer（行为序列编码）+ 静态特征融合 + 对比学习（声明vs行为偏差量化）
而非强行用GNN——数据集无图结构关系；而非LLM——不需要文本理解能力
```

### 3.4 技术方案

#### 核心技术栈

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| 行为编码层 | LSTM + Temporal Attention | 交易行为序列建模，捕捉风险偏好演变轨迹；LSTM对中等长度序列（50-200步）效果稳定 |
| 偏差量化层 | Contrastive Learning (声明嵌入 vs 行为嵌入) | 量化"声明偏好"与"行为偏好"的偏差距离，核心创新点 |
| 动态更新层 | Exponential Moving Average + 事件触发 | 市场波动事件后自动重新评估，而非年度问卷更新 |
| 可解释层 | SHAP + 行为特征归因 | 输出"为什么你的行为风险偏好是保守型"的具体行为证据 |
| 部署层 | FastAPI + Streamlit | 轻量级API+可视化Demo |

#### 模型架构

```
输入：客户交易流水序列 + 声明风险偏好（问卷结果）+ 市场行情 + 客户属性
  │
  ├─[行为路径] 交易序列 → LSTM+Attention → 行为风险嵌入 (128维)
  │
  ├─[声明路径] 问卷结果 → Embedding → 声明风险嵌入 (32维)
  │
  ├─[市场路径] 行情时序 → LSTM → 市场状态向量 (64维)
  │
  ├─[偏差量化] 行为嵌入 vs 声明嵌入 → Contrastive Loss → 偏差距离
  │
  ├─[融合层] 行为嵌入 + 声明嵌入 + 市场状态 + 客户属性 → 动态风险画像
  │
  └─[输出] 行为风险等级 + 声明-行为偏差预警 + 行为证据 + 建议调整
```

#### 创新点

1. **声明-行为对比学习**：首次用对比学习量化"客户说自己能承受的风险"与"客户实际承受的风险"之间的偏差——这是传统风偏评估完全缺失的维度
2. **事件触发动态更新**：市场波动超阈值时自动触发风险偏好重评估，而非等待年度问卷——从"静态声明"到"动态感知"的范式转换
3. **行为证据链**：不只输出风险等级，还输出具体行为证据（如"您在过去3次市场回调中均在下跌3%时赎回，行为风险偏好为保守型"）

### 3.5 价值亮点

## 四、主题三：CausalCredit — 因果推理增强信用评分系统

### 4.1 主题名称与一句话定位

**CausalCredit** — 不只预测风险，更是指导决策：因果推理增强的可解释信用评分系统

### 4.2 核心痛点

**痛点来源**：阿信报告方向#2（因果推理信用评分，8.90分）× 艾伦报告 C1（薄信用人群评估，24分，TOP4）

| 维度 | 痛点分析 |
|------|---------|
| **问题本质** | 传统信用评分只做预测（"谁会违约？"），无法回答决策问题（"降低利率能否减少违约？""提供信用辅导能否改善还款？"）。对于薄信用人群（新来港人士、应届毕业生），传统评分卡因缺乏信贷记录而无法覆盖 |
| **现有方案不足** | ① 传统评分卡（FICO/环联）仅基于相关性，无法量化干预效果 ② 对薄信用人群"一刀切"拒贷，浪费了替代数据中的有效信号 ③ 评分不可解释，客户不知道如何改善信用状况 |
| **真实案例** | 香港新来港人士超20万/年，无本地信贷记录，银行"不敢贷"；中小企融资缺口达HK$1,200亿 |
| **痛感强度** | ⭐⭐⭐⭐⭐ — 普惠金融刚需+BOCHK大湾区战略 |

### 4.3 数据集选型

| 数据集角色 | 数据集名称 | 规模 | 核心特征 | 为什么选它 |
|-----------|-----------|------|---------|-----------|
| **主数据集** | Home Credit Default Risk | 30万+条，120+特征 | 多表关联（申请表+历史信贷+信用卡+POS+ installment） | Kaggle经典竞赛数据，多表关联结构天然适合因果图构建；有干预变量（贷款条件） |
| **辅助数据集** | Lending Club Loan Data | 200万+条，150+特征 | 真实P2P贷款数据，含利率/等级/违约 | 真实数据，利率变化可作为因果干预变量 |
| **辅助数据集** | German Credit Risk (UCI) | 1,000条，20属性 | 混合类型特征（分类+数值） | 经典基准，适合因果发现算法验证 |

**数据集如何决定模型选型**：

```
数据集特性分析：
├── Home Credit（多表关联+干预变量）→ 决定使用因果推理（DoWhy/EconML）
│   └── 贷款条件（利率/期限/金额）可作为干预变量
│   └── 违约率可作为结果变量
│   └── 客户属性可作为混淆变量
├── Lending Club（利率变化+违约）→ 决定可做异质处理效应估计（CATE）
│   └── 不同利率水平对违约率的因果效应
└── 结构化表格数据 → 决定使用树模型（LightGBM）+ 因果推理
    └── 而非深度学习——表格数据上树模型通常优于DNN

模型选型结论：
DoWhy（因果发现）+ EconML（异质处理效应）+ LightGBM（预测基座）
因果推理是核心创新，LightGBM是高效基座——数据集特性决定技术选择
```

### 4.4 技术方案

#### 核心技术栈

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| 因果发现层 | DoWhy | Microsoft开源，因果图构建+效应估计+反驳验证一体化 |
| 处理效应层 | EconML (CATE) | 异质处理效应估计，量化"对不同客户降低利率的差异化效果" |
| 预测基座 | LightGBM | 表格数据SOTA，训练快，特征重要性天然可解释 |
| 可解释层 | SHAP + 反事实解释 | "如果降低利率2%，你的违约概率将从15%降至8%" |
| 部署层 | FastAPI + Streamlit | 轻量级API+交互式Demo |

#### 模型架构

```
输入：贷款申请数据 + 历史信贷数据 + 客户属性
  │
  ├─[因果发现] DoWhy → 因果图（贷款条件→违约率，控制混淆变量）
  │
  ├─[效应估计] EconML → CATE（不同客户群体的利率-违约因果效应）
  │
  ├─[预测基座] LightGBM → 违约概率预测
  │
  ├─[因果增强] 因果效应 → 修正预测 → 因果增强评分
  │
  ├─[反事实推理] "如果利率降低2%？" → 反事实违约概率
  │
  └─[输出] 信用评分 + 因果效应分析 + 反事实建议 + 可解释归因
```

#### 创新点

1. **从预测到决策的范式升级**：传统信用评分只回答"谁会违约"，CausalCredit回答"降低利率能否减少违约"——从预测性分析到规范性分析的跨越
2. **异质处理效应（CATE）**：量化"对不同类型客户，同一干预的差异化效果"——例如，降低利率对薄信用人群的违约降低效果可能远大于对优质客户
3. **反事实决策建议**：不只输出评分，还输出"如果调整贷款条件X，违约概率将变化Y%"——直接指导信贷决策

├── ASVspoof（语音数据）→ 决定使用音频模型（RawNet2/Wav2Vec2）
├── Bank Customer Segmentation（交易序列）→ 决定使用行为建模（LSTM/Isolation Forest）
└── 多模态数据 → 决定需要多模态融合（视觉+音频+行为）

模型选型结论：

### 5.4 技术方案

#### 核心技术栈

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| 视觉检测层 | EfficientNet-B4 (预训练) | FaceForensics++上AUC=0.98+，轻量高效（19M参数），单卡可训 |

| 行为基线层 | LSTM + Isolation Forest | 为银发客户建立"正常交易模式"，偏离即预警 |
| 融合层 | Weighted Score Fusion | 三模态评分加权融合（可学习权重），简单有效 |
| 部署层 | FastAPI + Gradio Demo | 交互式Demo，评委可上传视频/语音测试Deepfake检测 |

#### 模型架构

```
输入：视频通话/语音留言 + 交易行为 + 客户画像
  │
  ├─[视觉路径] 视频帧 → EfficientNet-B4 → Deepfake视觉评分 (0-1)
  │
  ├─[语音路径] 语音片段 → Wav2Vec2 → Deepfake语音评分 (0-1)
  │
  ├─[行为路径] 交易序列 → LSTM → 行为偏离度 (0-1)
  │            └─ Isolation Forest → 异常交易评分 (0-1)
  │
  ├─[融合层] 加权融合 → 综合防骗评分 (0-100)
  │
  └─[输出] 防骗评分 + 风险类型（Deepfake/异常转账/社交工程）+ 建议行动
```

#### 创新点

1. **多模态防骗融合**：首次将Deepfake检测（视觉+语音）与交易行为异常检测融合——现有方案要么只做Deepfake检测，要么只做交易风控，无人将两者结合
2. **银发族专属行为基线**：为60+客户建立专属"正常交易模式"（时段偏好、金额区间、收款人模式），偏离即预警——比通用风控模型更精准
3. **"守护者"交互设计**：不是冷冰冰的风险评分，而是"守护者"角色——用大字体、语音播报、子女联动等银发友好交互

### 5.5 价值亮点

| 维度 | 价值分析 |

## 六、主题五：ESG-Alpha — ESG因子动态定价引擎

### 6.1 主题名称与一句话定位

**ESG-Alpha** — 让ESG价值可量化：基于时序Transformer的ESG因子动态定价引擎

### 6.2 核心痛点

**痛点来源**：阿信报告方向#4（ESG因子动态定价，8.25分）× 艾伦报告 E9（ESG风险量化不足，20分）+ E11（绿色溢价定价难）

| 维度 | 痛点分析 |
|------|---------|
| **问题本质** | ESG投资的核心问题是"ESG因子到底值多少钱？"——ESG评分高的公司是否真的带来超额收益？绿色债券的利率优惠幅度应该多大？当前缺乏数据驱动的ESG因子定价工具，绿色溢价定价凭经验 |
| **现有方案不足** | ① ESG评分与资产定价的关联仅停留在相关性分析，无因果证据 ② 绿色贷款利率优惠（5-20bps）缺乏数据支撑，定价凭经验 ③ ESG因子的时变特征被忽视（ESG因子在不同市场环境下表现不同） |
| **真实案例** | BOCHK绿色贷款利率优惠10-15bps，但无法量化此优惠是否合理；ESG基金在2022年表现不佳引发"ESG是否真有Alpha"的争议 |
| **痛感强度** | ⭐⭐⭐⭐ — ESG+理财双赛道交叉痛点，定价问题是ESG投资的核心 |

### 6.3 数据集选型

| 数据集角色 | 数据集名称 | 规模 | 核心特征 | 为什么选它 |
|-----------|-----------|------|---------|-----------|
| **主数据集** | S&P 500 ESG Risk Ratings | ~500家公司 | E/S/G分项风险分+总分+行业 | ESG评分数据，作为因子输入 |
| **主数据集** | Yahoo Finance Dataset (2018-2023) | 多资产5年日线 | OHLCV+Volume | 真实行情数据，构建ESG因子收益 |
| **辅助数据集** | FRED (Federal Reserve Economic Data) | 80万+时间序列 | 宏观经济指标 | 控制宏观因子，分离ESG因子纯收益 |
| **辅助数据集** | World Bank Sovereign ESG Data | 国家级 | 主权ESG+自然资本+人力资本 | 扩展至主权ESG因子定价 |

**数据集如何决定模型选型**：

```
数据集特性分析：
├── Yahoo Finance（多资产行情时序）→ 决定使用时序模型（Transformer/TCN）
├── S&P 500 ESG（ESG评分+行业分类）→ 决定ESG因子作为条件输入
├── FRED（宏观指标时序）→ 决定需要多变量时序建模（控制宏观因子）
└── 时序+截面数据 → 决定需要面板数据模型

模型选型结论：
PatchTST（时序预测SOTA）+ 因子模型框架（Fama-French扩展）
ESG评分作为因子 → 时序Transformer预测ESG因子收益
而非GNN——无图结构；而非LLM——不需要文本理解
```

### 6.4 技术方案

#### 核心技术栈

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| 时序预测层 | PatchTST | ICLR 2023，长期预测SOTA，Patch分块+通道独立编码，金融时序表现优异 |
| 因子模型层 | Fama-French扩展 + 因果推理 | 经典因子模型框架扩展ESG因子，因果推理验证ESG→收益的因果效应 |
| 定价层 | Black-Litterman + ESG调整 | 将ESG因子收益纳入资产定价模型，量化绿色溢价 |
| 可解释层 | 因子归因分析 + SHAP | ESG因子对收益的贡献度归因，满足可解释性要求 |
| 部署层 | FastAPI + Streamlit | 交互式Demo，评委可调整ESG因子权重看定价变化 |

#### 模型架构

```
输入：ESG评分时序 + 资产行情时序 + 宏观指标时序
  │
  ├─[因子构建] ESG评分 → E/S/G分项因子 + 行业ESG因子
  │
  ├─[时序预测] PatchTST → 多资产收益预测（含ESG因子条件）
  │
  ├─[因果验证] DoWhy → ESG因子→收益的因果效应（非仅相关性）
  │
  ├─[定价模型] Black-Litterman + ESG调整 → 绿色溢价量化
  │
  └─[输出] ESG因子Alpha + 绿色溢价定价 + 因子归因 + 情景分析
```

#### 创新点

1. **ESG因子时变定价**：首次用时序Transformer捕捉ESG因子的时变特征——ESG因子在牛市/熊市/危机期间的表现不同，PatchTST可动态捕捉这种时变性
2. **因果验证ESG Alpha**：不只做"ESG评分高→收益高"的相关性分析，而是用因果推理验证"ESG因子是否真的带来超额收益"——解决"ESG是否真有Alpha"的争议
3. **绿色溢价数据驱动定价**：将ESG因子收益转化为绿色贷款/债券的利率优惠定价依据——从"凭经验定价"到"数据驱动定价"

### 6.5 价值亮点
